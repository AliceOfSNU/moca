# MOCA · Dots로 레스토랑 경영하기

모바일 우선 신청·체크인 사이트. Python 3.10+ 표준 라이브러리와 정적 HTML/CSS/JS만 사용합니다. 빌드·외부 서비스·결제·로그인·메일·분석 도구는 없습니다. 배포하지 않았으며 서버 운영자 검토용입니다.

## 실행

Linux/macOS에서 웹 파일과 분리된 **비공개 데이터 폴더**를 지정합니다.

```sh
cd website
python3 server.py --data ../private-signup-data --host 127.0.0.1 --port 8000
```

브라우저에서 http://127.0.0.1:8000 을 엽니다. HTML 파일 더블클릭으로 신청을 처리하지는 않습니다. 빌드 없이 위 서버로 실행합니다. 기본 바인드는 로컬 전용입니다. Windows에서는 fcntl이 없어 실행되지 않습니다. Linux 서버 운영을 권장합니다.

`--data`는 디렉터리입니다. `registrations.json` 하나에 답변을 저장하며 `.lock` 파일은 프로세스 간 잠금 용도입니다. website/ 내부 경로는 거부합니다. 서버는 소유자 전용 권한으로 데이터 폴더와 새 파일을 생성합니다. 기존 폴더 권한은 운영자가 확인하세요. 운영 데이터·복구 열쇠는 Git이나 공개 호스팅에 올리지 마세요.

`--host`로 바인드 주소를 바꿀 수 있습니다. 이 개발용 HTTP 서버를 인터넷에 그대로 노출하지 마세요. 공개 운영은 TLS 역방향 프록시, 프록시 Host 전달, 요청 속도 제한, 디스크 백업/복구, 모니터링 검토가 필요합니다. 공개 운영 시 정확한 오리진을 `--origin https://실제호스트`로 지정하세요. 이 작업에는 공개 배포가 포함되지 않습니다.

## 변경 가능한 행사 설정

정적 파일 밖의 JSON을 만들고 `--config /비공개경로/event.json`으로 실행하면 지정한 값만 기본값을 덮어씁니다. 알 수 없는 키는 거부합니다.

```json
{
  "title": "Dots로 레스토랑 경영하기",
  "date": "10월 10일 (토) 오전 11시~오후 1시",
  "venue": "당산역 인근 · [미정: 상세 장소]",
  "address": "",
  "capacity": 8,
  "fee": "6,000원",
  "signup_deadline": "[미정: 신청 마감]",
  "checkin_deadline": "[미정: 체크인 마감]",
  "fee_details": "[미정: 결제 방법·환불 기준]",
  "site_url": "[미정: 웹사이트 주소]"
}
```

상세 주소가 비어 있으면 주소 복사 버튼이 비활성화됩니다. 미정 값을 실제 사실처럼 표시하지 않습니다. 마감은 안내 문구이며 자동 마감 기능은 없습니다. 운영 방식/마감 시간대 확정 후 서버 검증을 추가해야 합니다. 현재 정원은 저장된 신청 수 기준 선착순 최대 8명이고 결제/선발 상태를 뜻하지 않습니다. 이 처리 방침은 공개 전 운영자 확인이 필요합니다.

`title`은 API 설정이며 현재 활동 제목은 HTML/JS에도 작성되어 있습니다. 다른 행사로 재사용한다면 제목·본문도 함께 바꾸세요. `site_url`은 API 설정이며 페이지 주소로 자동 이동하지 않습니다.

## 질문과 공개 여부

한 화면 한 질문, 진행률, 예상 소요 시간(신청 약 2~3분 / 체크인 약 1분)을 표시합니다.

1. 이름/별명: 필수, 기본 비공개. 마지막 질문에서 명시적으로 동의하면 공개합니다.
2. 하는 일: 필수, 회사명 없이 직군/활동만 수집. 이름 공개와 별도로 동의해야 함께 공개됩니다.
3. Dots 실제 접속 확인 상태: 필수, 비공개.
4. 노트북·Dots·FoodTruckBench 사전 과제 준비 가능 여부: 필수, 비공개.
5. 준비 중 막힌 점: 선택, 비공개. 최대 500자.
6. 이름/하는 일 공개 동의: 기본값 미동의. 수정해 동의를 취소하면 공개 목록에서 바로 빠집니다.
7. 체크인 준비 상태: 기존 신청자만, 비공개.
8. 체크인 막힌 점: 선택, 비공개.

연락처·이메일·나이·회사 이름·민감정보를 묻지 않습니다. 모든 질문 옆에 공개 여부를 표시합니다. 실제 참가자·후기·추천사를 미리 넣지 않았습니다.

## 동일인 수정 및 복구

첫 제출 **전에** 브라우저가 암호학적 난수 256비트 열쇠를 만들고 localStorage에 저장합니다. 서버에는 SHA-256 해시만 저장합니다. 같은 열쇠로 제출/재시도하면 기존 한 건을 수정하므로 정원이 늘지 않습니다. 동일한 이름만으로 수정하는 방식은 다른 사람의 사칭·비공개 답변 노출을 막을 수 없어 사용하지 않았습니다.

같은 열쇠의 이름 변경도 기존 신청 수정입니다. 다른 열쇠의 동일한 정규화 이름은 409로 거절하고 기존 답변을 제공하지 않습니다. 본인은 원래 기기나 복구 열쇠로 불러와야 합니다. 동명이인은 구별되는 별명을 사용합니다. 다른 열쇠·다른 이름으로 같은 사람이 다시 신청하는 것은 외부 본인 인증 없이 완전히 막을 수 없습니다. 이름 충돌 메시지를 통해 해당 별명의 사용 가능 여부는 추론할 수 있습니다.

완료 화면의 복구 열쇠는 **답변 열람·변경 권한 그 자체**입니다. 남에게 공유하지 않고 개인적으로 보관해야 합니다. 브라우저 데이터 삭제, 시크릿 모드 종료, 다른 기기 사용, 저장 차단 시 열쇠 없이는 자동 복구하지 못합니다. 서버는 열쇠 원문을 복원하지 못합니다. 이메일 기반 복구는 없습니다. 복구 열쇠를 잃은 경우의 운영자 확인/초기화 정책은 미정입니다. 공용 기기 사용을 피하세요. 현재 기기에서 열쇠를 지우려면 사이트 데이터 삭제 기능을 사용하세요.

제출 전 답변은 메모리에만 유지됩니다. 이전 버튼은 답변을 유지하지만 새로고침하면 미제출 내용은 사라집니다. 저장 완료된 답변은 새로고침/재방문 시 키로 불러옵니다. 네트워크 오류 시 답변을 보존하며 재시도할 수 있습니다. 버튼은 전송 중 비활성화됩니다.

## 데이터 구조

```json
{
  "version": 1,
  "registrations": [
    {
      "key_hash": "sha256-hex",
      "name": "participant supplied",
      "occupation": "participant supplied",
      "access": "ready | checking | blocked",
      "preparation": "yes | checking",
      "roadblocks": "optional private answer",
      "share_name": false,
      "share_occupation": false,
      "created_at": "UTC ISO-8601",
      "updated_at": "UTC ISO-8601",
      "checkin": null
    }
  ]
}
```

체크인 뒤 `checkin`은 `state` (`done|partial|not_started`), `roadblocks`, `updated_at` 객체입니다. 예시는 스키마 설명이며 실제 데이터가 아닙니다.

## API와 보안

- GET /api/public: 설정, 총 신청 수, 명시적 동의가 있는 이름/하는 일만 반환합니다. 접속·준비·막힌 점·체크인·열쇠 해시는 공개하지 않습니다.
- POST /api/me: 64자리 복구 열쇠를 본문에 보낸 본인의 기록만 반환합니다.
- POST /api/signup: 열쇠 기준 생성/수정. POST /api/checkin: 기존 기록만 갱신합니다.
- 모든 POST는 application/json과 X-Moca-Request: 1 헤더가 필요합니다. 다른 Origin/Sec-Fetch-Site, 허용되지 않은 Host를 거부합니다. CORS를 열지 않습니다.
- 8 KiB 본문 제한, 문자열 길이/선택값/boolean 검증, 요청 타임아웃, 일반화된 오류 메시지를 사용합니다. 키를 URL이나 로그에 쓰지 않습니다.
- 응답은 no-store, CSP, nosniff, frame 차단, no-referrer를 적용합니다. 사용자 문자열을 HTML escape하여 렌더링합니다.
- 정적 파일 **명시적 허용 목록**: `/`, `/index.html`, `/style.css`, `/app.js`, `/banner.png`만 제공합니다. JSON/Python/README/.env/기타 파일/디렉터리 탐색을 제공하지 않습니다. 정적 파일의 심볼릭 링크도 거부합니다.
- 정원 검증·동일인 확인·변경·atomic replace를 한 잠금 범위에서 수행합니다. 스레드 잠금과 fcntl 프로세스 잠금을 함께 사용합니다. 중간 쓰기 파일은 비공개 데이터 폴더에만 생성합니다. 손상된 JSON을 빈 데이터로 덮어쓰지 않습니다.
- 외부 본인 인증, 도용된 열쇠 복구/회수 UI, 요청 속도 제한, 운영자 대시보드, 암호화 저장, 자동 보관 기한/삭제, 결제/환불, 대기자 기능은 없습니다. 공개 운영 전 위 항목과 개인 정보 운영 정책을 검토해야 합니다.

## 행사 운영상 확인할 점

- 수정 요청서에 남은 '두 서비스 접속'은 Dots-only 기획과 불일치합니다. 본 구현은 Dots만 대상으로 했습니다.
- FoodTruckBench 실행 방법·공통 설정·시작 시점, Dots 실제 이용 조건/추가 비용, 정확한 장소와 주소, 신청/체크인 마감, 참가비 결제/환불, 데이터 보관/삭제와 복구 정책을 확정해야 합니다.

## 이번 검증 결과

- 통과: Python 문법, JavaScript 문법, 로컬 HTTP 신청/재시도/수정/동명이인 차단/체크인/복구 키 조회/공개 동의 및 철회/공개 API 비공개 필드 미노출.
- 통과: 20건 동시 신청 중 정원 잔여 7건만 저장, 총 8건 유지, 정원 이후 기존 수정/체크인 허용.
- 통과: 본문 크기/선택값/동의 자료형 검증, 다른 Origin/Host 차단, localhost와 127.0.0.1 정상 요청, 비허용 파일·경로 탐색·인코딩 경로·심볼릭 링크 차단.
- 별도 검토 통과: 진행 중인 저장과 다른 신청 복구가 겹치는 비동기 경쟁 및 화면을 떠난 뒤 늦은 응답에 의한 강제 이동 방지.
- 미실행: 실제 브라우저의 모바일/데스크톱 시각 검수, 터치/키보드 접근성, 뒤로가기/새로고침/오류 재시도 전체 사용자 흐름. 테스트 스크립트는 준비했으나 실행 환경의 Chromium 프로세스가 socket EPERM으로 중단되고, 클라우드 브라우저는 localhost를 차단하여 화면을 확인하지 못했습니다. 실제 운영 전 소유자 환경에서 반드시 확인하세요.
- 테스트는 별도 임시 폴더의 가짜 데이터만 사용했습니다. 배포 폴더에는 실제/가짜 신청 데이터나 테스트 파일이 없습니다.
