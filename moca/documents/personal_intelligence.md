### 개인 맞춤과 운영 의견 반영을 위한 개인 데이터 기록
먼저 1:1 dm을 통한 데이터 추출부터 시작한다. 

1. 첫 개발 대상은 ‘운영에 활용할 수 있는 멤버의 의향’이라는 데이터야.

지금은 정보가 개별 채팅 컨텍스트에만 있어서, 다른 세션에서 활용하려면 원문을 넘기거나 다시 읽어야 하잖아. 그 사이에 출처와 사용 허가가 붙은 지속적인 기록을 하나 두는 거야.

예를 들어 멤버가 이렇게 말했어.

“AI로 음악 만드는 걸 같이 해보고 싶어요. 설명만 듣는 것보다 직접 만들어보는 게 좋아요.”

처음에는 다음 정도를 기록할 수 있겠지.
| 항목      | 예시                         |
| ------- | -------------------------- |
| 원하는 경험  | AI로 음악을 직접 만들어보기           |
| 선호하는 형식 | 설명 위주보다 함께 실습              |
| 의향의 단계  | 관심 있음 — 참가나 주최를 약속한 것은 아님  |
| 출처      | 해당 멤버의 DM 메시지 참조           |
| 허용 범위   | 개인 경험을 최적화 하는데만 사용 / 공동 활동 기획 및 운영에 활용 |


처음부터 성격이나 인간관계까지 모델링하기보다는 궁금한 질문, 해보고 싶은 활동, 나눌 수 있는 경험, 참여 조건 정도로 시작하는 게 좋아. 

그리고 이 기록은 게시판과 별도의 저장소에 두는 편이 맞겠어. 게시판은 멤버가 읽는 콘텐츠 공간이고, 이 기록에는 멤버별 권한과 정보의 허용범위가 달라.

2. 정보 추출은 기존 chat agent에 작은 도구 하나를 붙여 시작할 수 있어.

지금 단계에서는 모든 로그를 읽는 별도 추출 에이전트부터 만들지 않아도 돼. 대화 중인 모카가 맥락을 가장 잘 알고 있으니, propose_member_data 같은 도구로 기억 후보를 제안하게 하는 거야.

여기서 역할을 나눠.

모델: 무엇을 기억할 가치가 있는지 해석하고, 후보 내용을 작성한다.
하네스: 현재 세션의 멤버에게 후보를 귀속시키고, 기본적으로 개인 영역에 저장한다.
멤버: /memory를 통해 에이전트가 나에 대해 기억하는 정보를 확인하거나, 정보 활용을 허락할 범위를 선택한다.
하네스: 그 확인 결과에 따라 공유 가능한 기록을 만든다.

모델이 member_id를 임의로 지정하거나, approved: true라고 써서 공유를 승인할 수는 없게 해야 해. 그런 값은 인증된 세션과 실제 사용자 입력에서 하네스가 정하는 거지.


3. 멤버의 동의와 투명성
대화 기록이 컴퓨터에 남는다는 것은 이미 사용자에게 동의를 받았고, 이제 정보의 활용 범위에 대해서 동의를 구해야 해. 처음부터 많은 걸 들이밀면 유저가 머리아플 수도 있어. 정보 추출은 첫 dm 턴부터 시작하지 말고, 멤버가 모임에 가입한 다음날 아침에 이런 것도 있다는 식으로 모카가 얘기하는 식으로 허락을 구하자.

졍보 추출 자체는 문제가 되지 않아. 이미 저장된 데이터를 가공하는 거라, 활용범위만 얘기하면 돼. 활용 범위는 개인의 모임 경험 개선(활동 추천 등)과 운영을 위한 모임 전체 레벨 지식 베이스에 활용(모임의 관심사 추적 등)를 분리해서 생각해야돼. 일단 일괄적으로 허락을 받고 언제든 끌 수 있다고 말해. 여기서 '정보'는 유저가 채팅에 직접 입력한 것만으로 유추된 정보만이라고 다시 안심시켜줘.

유저가 활용 범위를 수정하는 방법에 대한 UI는 나중에 생각해보자.

유저는 원한다면 모카가 자신에 대해 무엇을 기억하고 있는지 물어볼 수 있어. 모카는 기록 전체를 그대로 옮기기 보다는 일단 짧게 요약해서 답하고, 기록 전체를 원하면 모임장에게 요청하도록 안내해.

### 구현 메모 (1, 2번 항목)

- **저장소** (`chatbot/members.py`): 게시판·채팅 기록과 분리된 `data/members/<멤버>/notes.jsonl`.
  한 줄이 기록 하나: kind(궁금한 질문/해보고 싶은 활동/나눌 수 있는 경험/참여 조건), summary, format,
  stage(관심 있음→참여 의사→주최 의사), source(맥락·시각·근거 인용), scope(personal=true, moim=false), 타임스탬프.
  비슷한 기록은 새로 쌓지 않고 갱신하며, 멤버가 더 약속했을 때만 stage가 올라간다.
  확인: `python -m chatbot.members list|show <멤버>`.
- **추출** (`chatbot/member_tool.py`): 대화 중인 모카가 `propose_member_data` 도구로 후보를 제안한다.
  모델은 내용만 쓰고, 귀속과 활용 범위는 하네스가 정한다 — 1:1에서는 대화 상대로 고정, 모임 채팅에서는
  방금 말한 멤버로만 제한(그 외 이름은 도구 오류로 거절), scope는 항상 개인 영역, 한 답장에 최대 3건.
  모델이 member나 승인 여부를 지정할 수 없다.
- **활용**: 1:1 프롬프트에는 그 멤버의 기록이 붙고(다른 멤버·모임 채팅에 옮기지 말라는 지시 포함),
  모임 채팅 답장에는 붙이지 않는다. 수집은 1:1과 모임 채팅 모두에서 한다.

### 구현 메모 (3번 항목)

- **묻는 시점** (`chatbot/memory_consent.py`의 `due`): 1:1 안내에 동의한 **다음 날** 아침(`run.py --memory-hour`,
  기본 9시)에 한 번. 같은 날에는 묻지 않아 첫 대화 위에 겹치지 않는다. 이 기능 이전에 이미 동의한 멤버는
  다음 아침 차례가 온다. 전송에 실패하면 다음 날 다시(최대 3회), 성공하면 멤버당 한 번뿐이고 조르지 않는다.
- **묻는 방식**: 모카가 자기 말투로 쓴다. 반드시 담아야 할 내용은 `documents/memory_scope_request.txt`에
  목록으로 두고 프롬프트에 넣는다(문구를 그대로 보내지 않는다).
- **답의 판정**: 대화 중인 모카가 아니라 **별도 호출**이 최근 대화를 읽고 동의/거절/불명확만 판정한다
  (`memory_consent.classify`). 분명할 때만 '동의'이고, 기록은 하네스가 쓴다. 불명확이면 다음 답장에서 한 번
  가볍게 다시 묻고, 세 번 불명확하면 더 묻지 않는다(공유는 꺼진 채로).
- **멤버의 스위치**: 1:1에서 `/memory`(무엇을 기억하는지 짧은 요약 + 현재 상태), `/memory on`, `/memory off`.
  명령은 하네스가 직접 처리하고 모델은 확인 문장만 쓴다.
- **범위의 적용**: 동의는 이미 쌓인 기록에도 적용되고, 끄면 즉시 모두 비공유로 돌아간다
  (`members.set_moim_scope`). 끄더라도 1:1 맞춤에는 계속 쓰이고 기록 자체는 지워지지 않는다.
- **운영 쪽에서 보이는 것**: 운영 모카는 동의한 멤버의 기록만 **이름과 함께** 본다
  (`admin/agent.py`의 `shared_member_interests`). 동의하지 않았거나 끈 멤버는 한 줄도 넘어가지 않는다.
- **확인**: `python -m chatbot.memory_consent` (누구에게 물었고 무엇이라 답했는지), `python -m chatbot.dm ask-scope`.
- **아직 없음**: 모임 전체 레벨의 집계 지식 베이스(지금은 멤버별 기록을 그대로 넘긴다), 활용 범위를 바꾸는
  앱 안의 UI(`/memory` 명령이 그 자리를 대신한다), 정모 초대 DM 파이프라인.
