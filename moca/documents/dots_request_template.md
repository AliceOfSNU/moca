## 모든 산출물에 공통으로 지킬 것

1. **적힌 것만 사실로 써.** 위에 없는 일정·장소·비용·인원·규칙을 만들어 내지 마. "미정"으로 적힌 것은
   [미정: 시작 시각]처럼 대괄호로 남겨 — 사람이 채운 뒤에 게시해. 날짜와 요일도 위에 적힌 그대로만 써.
   계산해서 요일을 붙이지 마.
2. **모카가 해 주겠다고 약속하지 마.** 모카가 할 일은 이 요청서에 적힌 것뿐이야. "모카가 1:1로 안내해
   드려요", "모카가 결과를 정리해 드려요" 같은 문장을 넣고 싶으면 넣지 말고 `questions.md`에 물어봐.
3. **사람을 지어내지 마.** 참가 후기, 추천사, 진행자 이름, 예시 참가자 이름을 만들지 마.
4. **모르겠으면 추측하지 말고 물어.** 확인이 필요한 것은 `questions.md`에 적어. 우리는 너와 직접 대화할 수
   없어서, 네가 물어보지 않은 것은 네가 정한 대로 나가.
5. **말투:** 모카 계정으로 올라가는 글이야. 모카는 장난스럽지만 따뜻하고, 친구처럼 편하게 말해. 멤버를
   상대로 쓰는 글은 해요체로. 딱딱한 공문서 말투나 과장된 광고 문구는 피해.

### 시각 정체성

모든 이미지와 웹사이트는 같은 모임에서 나온 것처럼 보여야 해. 참고 파일은 `MOCA/workspace/activities/example/`에 있어.

- `MOCA/workspace/activities/example/moca_anime.png`, `MOCA/workspace/activities/example/moca_real.png` — 모카.
  같은 캐릭터를 두 가지 그림체로 그린 거야: 일러스트와, 실제 인형에 가까운 그림. 어느 쪽이든 아래 특징이 그대로
  보여야 같은 모카로 알아봐 — 하얗고 복슬복슬한 털, 안쪽이 분홍빛인 긴 토끼 귀, 분홍빛의 큰 눈, 귀에 걸린
  별 장식 금색 고리, 가슴의 분홍 별. 배너에는 모카가 들어가야 하고, 그림체는 활동 분위기에 맞는 쪽으로 골라.
- `MOCA/workspace/activities/example/banner.png` — 지난 활동의 배너. 분위기 참고용이야. 그대로 베끼지는 마.
- 기본 색: 검정 바탕에 흰색(#FFFFFF), 초록(#00C55F), 보라(#9652FA), 파랑(#006AFE). 활동의 분위기에 맞게
  바꿔도 되지만, 바꿨다면 `manifest.json`의 notes에 이유를 적어 줘.

**이미지 안에 한글을 넣지 마.** 생성된 한글 글자는 자주 깨져. 글자가 꼭 필요하면 짧은 영문 제목과 숫자만.
한글 안내는 모두 텍스트 파일과 웹사이트가 맡아.

## 산출물 1. 활동 소개글 — `introduction-post.md`

소모임 게시판에 그대로 올릴 글이야. 이 글을 읽은 멤버가 "무엇을 하는 자리이고, 나도 해도 되고, 어떻게
신청하는지"를 알 수 있어야 해.

- **첫 줄은 제목.** `# ` 다음에 40자 이내로. 소모임 게시판 제목 칸에 그대로 들어가.
- 본문 순서:
  1. 무엇을 하는 자리인지 한두 문장
  2. 왜 해 볼 만한지 — 참가자가 얻는 것({{activity_goal}})을 참가자의 말로
  3. 누구에게 맞는지, 그리고 **무엇이 없어도 되는지** (경험, 장비, 전문 지식 등). 망설이는 사람이 읽어도
     "나도 되겠네" 할 수 있게
  4. 미리 할 것과 당일 흐름 — 길게 풀지 말고 핵심만
  5. 일정·장소·인원·비용·신청 방법을 목록으로
- 신청 방법에는 웹사이트 주소를 넣어: {{site_url}}
- **게시할 글만 넣어.** "게시 대상", "게시 전 확인할 것" 같은 우리에게 하는 말은 이 파일에 넣지 말고
  `questions.md`에 적어. 이 파일은 손대지 않고 그대로 올라갈 수 있어야 해.
- 길이는 소모임 앱 화면에서 스크롤 두세 번이면 읽을 수 있을 만큼.

## 산출물 3. 활동 배너 — `banner.png`

이 활동을 한눈에 보여 주는 가로로 긴 그림이야. 게시글 맨 위, 웹사이트 첫 화면, 모임 공지 노트의 머리에 같이
쓰여.

- 크기: 1600×900 픽셀 (16:9).
- 모카가 들어가야 해. 모카가 이 활동을 하고 있는 모습이면 더 좋아.
- 활동이 무엇인지 그림으로 알 수 있게. 예를 들어 푸드트럭을 운영하는 활동이면 푸드트럭이 보이게.
- 글자는 위의 규칙대로 — 없거나, 영문 제목과 날짜 숫자만.
- 왼쪽이나 오른쪽 한쪽에 여백을 두어. 웹사이트에서 그 자리에 제목 글자를 얹을 수 있게.

## 산출물 4. 모임 공지 노트 — `header.png`, `middle.png`, `footer.png`, `recruit.txt`

activity 소개/홍보글을 가독성 좋게 이미지로도 뽑을 거야. 이 홍보용 이미지를 '모임 공지 노트'라고 부르자.
예시 모임 공지 노트는 `MOCA/workspace/activities/example/모임공지노트.png`를 살펴봐. 너가 만들 산출물은 완성된 모임 공지 노트
이미지가 아니라, python script가 모임 공지 노트를 조립하는 데 필요한 재료 이미지 3개와 텍스트 파일
하나야.

### 모임 공지 노트의 배경으로 쓸 이미지를 만들기

이미지는 세 장을 만들어야 돼. 노트의 길이를 미리 확정할 수 없어서 세로 방향으로 이어 붙일 수 있게 세
부분으로 나누어 만들어야 돼. header, 중간 부분, footer.

- **header**는 산출물 3에서 너가 만든 banner 이미지와, 텍스트가 들어갈 모서리 둥근 박스의 윗부분을
  포함해야 돼.
- **footer**는 header의 요소들을 재활용해서 같은 분위기의 간단한 그림을 그려 주고(footer의 이미지는
  복잡하게 만들지 마. 어차피 아무도 footer까지 자세히 안 봐), 박스의 둥근 아랫부분을 포함해야 돼.
- **중간 부분**은 박스의 중간 부분을 포함해야 돼. 내용이 길어지면 중간 부분을 여러 장 이어 붙여서
  박스의 크기를 조절할 거야.

위, 중간, 아래의 박스가 자연스럽게 이어지도록 크기가 맞아야 돼. 이어 붙일 때 연결선이 어긋나지 않도록
위·중간·아래를 한 캔버스에서 설계한 뒤 세 파일로 나누어. 텍스트가 들어갈 박스 안은 비워 두고, 반복되는
중간 구간은 높이가 늘어나도 티가 나지 않게 단순하게 만들어.

조립하는 프로그램이 박스를 스스로 찾을 수 있게, 다음을 지켜 줘:

- 세 장 모두 **가로 1080픽셀**로 같게.
- **박스 안쪽은 한 가지 밝은 색으로 평평하게** 칠해. 무늬나 그라데이션을 넣지 마. 박스 바깥과 확실히
  구분되는 색이어야 해.
- **middle.png는 모든 가로줄이 똑같아야 해.** 위에서 아래로 어디를 잘라도 같은 모양 — 그래야 몇 장을
  붙여도 이음매가 안 보여.
- header의 맨 아랫줄과 footer의 맨 윗줄에서 박스는 middle과 같은 폭, 같은 위치여야 해.

세 파일의 확장자는 png, 이름은 header, middle, footer여야 돼. 그래야 나중에 프로그램이 파일들을 검색해서
찾을 수 있어.

### 모임 공지 노트에 들어갈 텍스트를 작성하기

텍스트는 기본적으로 모임을 홍보하면서, 신청자들이 신청에 앞서 미리 알아야 할 내용들을 고지하면 돼.
산출물 1에서 줄글로 표현한 member-facing activity description의 내용을 가독성 좋게 일부 포함해.

1. 산출물 1의 내용 중 필수 정보만 남기고 디테일들은 생략
   - 시간, 장소, 비용, 참여 인원은 필수 정보야.
   - 어차피 산출물 1의 글 자체도 모임 sign up 받을 때 올릴 거니까 산출물 1의 모든 내용을 옮겨 적을 필요가
     없어.
2. 적절한 이모티콘으로 가독성 높이기
   예: ⏰ 시간 / 📍 장소 / 👥 참여 인원 / 💰 비용
3. 가능하면 줄글 대신 ordered/bullet point list 사용, 줄글은 짧게 유지.
4. 제목 줄은 `### `로 시작해. 그 아래 소제목은 `#### `. 조립하는 프로그램이 이 두 가지를 큰 글자·굵은
   글자로 그려. 그 밖의 마크다운(표, 링크, 굵게)은 쓰지 마 — 그대로 글자로 찍혀.

text file의 이름은 `recruit.txt`로 해.

## 산출물 7. 신청·체크인 웹사이트 — `website/`

멤버가 이 활동에 **신청**하고, 당일 모이기 전에 **체크인**(준비를 마쳤는지 확인)하는 웹사이트야. 모카의
서버에서 돌아가. 주소: {{site_url}}. 예시 요청서는 `MOCA/workspace/activities/example/website.md`, 지난 활동에서 실제로
쓴 사이트는 `MOCA/workspace/activities/example/website/`에 있어.

### 페이지

1. **안내 페이지** — 배너, 활동 이름, 일정·장소·인원·비용, 진행 방식 요약, 신청 버튼. 산출물 1과 같은
   내용을 짧게.
2. **신청** — 이름과 하는 일, 그리고 이 활동에 맞는 질문 몇 개. 예를 들어 미리 준비할 것이
   ({{participant_prep}}) 있다면 그것을 할 수 있는지.
3. **체크인** — 신청한 사람이 당일 전에 준비를 마쳤는지. 미리 할 것을 끝냈는지, 막힌 곳이 있는지. 체크인
   마감은 {{checkin_deadline}}.
4. **끝 화면** — 고맙다는 인사, 일시, 장소, 복사할 수 있는 주소.

### 지켜야 할 것

지난 활동의 사이트를 만들고 고치며 배운 것들이야. 전부 실제로 생겼던 문제야.

- **한 화면에 한 질문.** 진행 막대로 어디쯤인지 보여 주고, 처음에 "몇 분이면 끝나요"를 알려 줘.
- **묻는 자리마다 공개인지 비공개인지 적어.** 안내 페이지에 보여 줄 답(예: 이름, 공개를 고른 링크)과
  진행 준비용으로만 쓸 답을 나누고, 그 질문을 묻는 화면에서 바로 알려 줘.
- **꼭 필요한 것만 물어.** 연락처, 이메일, 나이, 회사 이름은 묻지 마. 소모임 안에서 이미 서로를 찾을 수 있어.
- **같은 사람이 두 번 보내도 한 번으로.** 보내는 중에는 버튼을 막고, 같은 이름으로 다시 내면 앞의 것을
  고치는 것으로 처리해. 다시 들어온 사람에게는 "이미 신청했어요 — 고칠래요?"를 보여 줘.
- **받은 답을 저장하는 곳은 웹에서 내려받을 수 없는 곳이어야 해.** 화면 파일과 같은 폴더에 두면 누구나
  주소를 쳐서 남의 답을 내려받을 수 있어. 서버는 정해 둔 종류의 파일(html, css, js, 이미지)만 내보내고 그 밖의
  것은 내보내지 마.
- **휴대폰에서 먼저.** 대부분 폰으로 소모임 링크를 눌러 들어와. 글자 입력칸은 16px 이상(작으면 iOS가 확대해).
- **바깥 서비스를 쓰지 마.** 웹 글꼴(Google Fonts) 말고는 외부 스크립트, 분석 도구, 로그인, 결제, 메일 발송을
  넣지 마.

### 만드는 방식

- 화면은 HTML, CSS, JavaScript 파일로. 빌드 도구 없이 그대로 열리게.
- 서버는 Python 표준 라이브러리만 쓰는 파일 하나(`server.py`)로. 받은 답은 파일 하나(JSON)에 쌓아. 데이터베이스는
  필요 없어. 저장할 폴더는 `--data` 같은 실행 옵션으로 받게 해 줘.
- `website/README.md`에 실행 방법, 받는 질문 목록과 각각의 공개 여부, 저장 파일의 모양을 적어 줘. 우리가
  읽고 검토한 뒤에 서버에 올릴 거야.

## 결과물을 올리는 방법

`{{output_folder}}`에 아래 이름 그대로 올려 줘. 하네스가 이 이름으로 파일을 찾아서 모카의 서버로 내려받아.

```
introduction-post.md
banner.png
header.png
middle.png
footer.png
recruit.txt
website/          (README.md, server.py, 화면 파일들)
questions.md      (확인이 필요한 것이 있을 때만)
manifest.json     ← 맨 마지막에
```

**`manifest.json`은 다른 파일을 전부 올린 다음 마지막에 올려.** 하네스는 이 파일이 생기는 것을 보고 "다
됐다"고 판단해. 먼저 올리면 반쯤 올라간 파일을 가져가게 돼.

```json
{
  "request_id": "{{request_id}}",
  "files": ["introduction-post.md", "banner.png", "header.png", "middle.png", "footer.png",
            "recruit.txt", "website/README.md", "..."],
  "questions": true,
  "notes": "우리에게 하고 싶은 말. 색을 바꿨다면 그 이유도."
}
```

- `files`에는 실제로 올린 파일을 모두 적어 (website/ 안의 파일도 하나씩).
- 하나라도 만들지 못했으면 `files`에서 빼고 `notes`에 이유를 적어. 만든 척하지 마.
- `questions`는 `questions.md`를 올렸으면 true.
